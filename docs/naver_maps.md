# 만남 장소와 모임 지도 — 2026-10-07

## 구현 범위

- 만남 생성/수정의 장소 입력 바로 아래에서 검색 화면을 연다. 지역+장소 이름으로 검색하고 후보의 이름·주소·핀을 확인한 뒤 선택한다. 네이버 지역 검색 API는 한 요청에 최대 5개 후보를 제공한다.
- 검색에 없는 장소는 지도를 길게 눌러 핀을 선택한다. 주소 없는 수동 핀도 저장할 수 있지만 지역 순위에서는 제외한다. GPS나 현재 위치 권한을 요구하지 않는다.
- 선택한 장소의 이름/주소/WGS84 좌표/출처를 `meetups.place` JSONB 한 개에 저장한다. 기존 `location` 문자열은 유지한다. 이번 버전은 **만남당 장소 한 곳**이며 여러 장소·유료 제한은 적용하지 않는다.
- 장소 문자열을 직접 바꾸면 이전 좌표를 해제한다. ‘지도 위치만 지우기’는 장소 문자열을 유지한다. 변경은 최종 기록 저장에 성공한 때만 반영된다.
- 만남 상세에는 선택한 장소의 지도와 주소를 표시한다. 모임 상세 정보에는 전체 만남의 장소 핀을 표시하고 모든 핀이 보이는 범위로 카메라를 맞춘다. 한 지점이면 줌 15를 사용한다.
- 같은 좌표(소수점 6자리 기준)의 방문은 핀 하나로 묶고 방문 횟수를 표시한다. 핀 또는 목록을 누르면 해당 장소의 만남 제목과 날짜를 볼 수 있다.
- ‘우리가 자주 만난 지역’은 주소의 시/도+시/군/구로 만남 횟수를 집계한다. 동명 구를 합치지 않으며, 수원시 영통구처럼 일반구도 구분한다. 순위 항목을 선택하면 해당 지역 핀만 표시하고 줌을 다시 맞춘다.
- 첫 만남 목록 페이지만으로 계산하지 않고 장소가 있는 기록을 전체 페이지 조회한다. 좌표 없는 기존 기록은 자동 위치 추정 없이 그대로 유지한다.

## 아직 필요한 외부 설정

**실제 Supabase에 이번 SQL이나 서버 함수를 적용하지 않았다. API 키도 추가하지 않았다.** 앞선 회원 이력/작성자 SQL은 사용자에게 적용 완료로 인계받았지만 이번 세션에서 실제 DB를 다시 조회하지 않았다.

1. 기존 DB의 컬럼·트리거·RLS를 확인하고 별도 테스트 프로젝트에서 [추가 migration](../supabase/migrations/20261008000000_meetup_places.sql)을 검증한다. 이후 운영 DB에 이 파일만 추가 적용한다. 기존 초기화/reset SQL을 재실행하지 않는다.
2. 네이버 Maps 콘솔에서 Android 패키지/iOS bundle과 사용할 상품을 등록한다. 클라이언트 식별자를 앱 `.env`의 `NAVER_MAP_CLIENT_ID`에 넣는다. 지도 client secret은 앱에서 사용하지 않는다. 배포 대상·제공 범위·요금과 콘솔 설정은 저장소만으로 검증할 수 없다.
3. 네이버 Developers에서 **지역 검색 API** 애플리케이션을 준비한다. 지도 SDK 식별자와 검색 API 인증은 별개다. `NAVER_SEARCH_CLIENT_ID`와 `NAVER_SEARCH_CLIENT_SECRET`을 Supabase Edge Function secrets에 설정한다. **검색 secret을 Flutter `.env`나 Git에 넣지 않는다.**
4. [naver-place-search](../supabase/functions/naver-place-search/index.ts) 함수를 배포한다. 함수가 직접 `auth.getUser()`로 토큰을 검증하고 해당 모임의 활성 멤버십을 확인한다. ES256 토큰의 gateway 호환 문제가 있는 환경에서는 `supabase functions deploy naver-place-search --no-verify-jwt`로 배포할 수 있으며, 함수 내 인증·모임 권한 확인은 유지된다.
5. 앱을 새로 빌드하고 실제 기기에서 지도 인증·후보 검색·저장/수정/삭제·모임 지도·줌을 검증한다. Android SDK와 iOS 빌드 도구가 없는 이 클라우드에서는 네이티브 빌드와 실제 렌더링을 검증하지 못했다.

SDK는 `flutter_naver_map` 1.4.4로 연결했다. Android/iOS 전용 Flutter 래퍼이며 네이버 공식 Flutter SDK는 아니다. 웹/데스크톱과 키 미설정·지도 인증 실패에서는 안내 영역을 표시한다. 검색 함수가 준비되면 지도 렌더링 없이도 후보 이름/주소를 선택할 수 있다. 지도 검색 실패가 기존 장소 텍스트 입력이나 기록 조회를 막지는 않는다.

DB migration 전에는 모임 지도 조회가 오류 안내/재시도 상태로 표시된다. 장소를 선택하지 않은 기존 방식의 저장은 원래 RPC를 사용한다. 좌표 선택/해제 저장은 새 RPC가 필요하며, 함수가 없으면 저장 실패로 처리한다. 좌표를 조용히 버리고 텍스트만 저장하지 않는다.

## 저장과 접근 권한

추가 RPC `save_meetup_with_place_atomic`은 SECURITY INVOKER로 기존 meetups/attendances RLS를 그대로 적용한다. 장소·기록·참석은 같은 DB 트랜잭션으로 저장하며 참석 저장 실패 시 모두 롤백한다. 기존 `save_meetup_atomic`은 수정하지 않으며 기존 클라이언트의 텍스트 수정이 좌표를 지우지 않는다.

서버 검색은 로그인·활성 모임 멤버 확인을 거친다. 사용자별 분당 30회/UTC 일당 300회로 제한한다. 이 제한은 전체 서비스의 네이버 사용량 한도를 보장하지 않으므로 제공자 콘솔의 실제 quota/사용량도 운영 시 확인해야 한다. 비공개 카운터는 일반 테이블 API 접근을 차단하고 7일보다 오래된 사용 카운터는 후속 검색에서 정리한다. `service_role` 키를 사용하지 않는다.

네이버 원본 응답·토큰·secret은 클라이언트에 전달하거나 로그로 출력하지 않는다. 지역 검색 `mapx/mapy`는 WGS84 값 × 10^7이므로 위경도로 변환·검증해 반환한다. 응답 HTML 제목은 제거한다. 기기에서 회원별 수정/삭제 권한과 탈퇴 이력은 기존 검증 항목을 유지한다.

## 구 경계를 색칠하는 지도

현재 화면은 **지역별 순위와 해당 지역의 장소 핀 필터**다. 구 경계 다각형이나 색칠 지도는 아직 연결하지 않았다. 주소 파싱은 공식 행정구역 코드 판정이 아니며, 주소가 없거나 분류할 수 없는 만남은 순위에서 제외하고 그 수를 설명한다.

구별로 잘린 PNG를 직접 모으기보다 공식 행정경계 데이터를 사용하도록 권장한다. 다음 공급자에서 시군구 경계 데이터를 검토할 수 있다.

- [공공데이터포털: 시군구 행정구역 WMS/WFS](https://www.data.go.kr/data/15059008/openapi.do)
- [SGIS 개발지원센터](https://sgis.kostat.go.kr/developer/): 행정구역 코드와 경계 API

후속 구현에서는 사용 조건·출처 표시·경계 기준 연도·일반구 제공 여부를 확인하고, 공급자의 좌표계에서 WGS84로 변환한 GeoJSON을 준비한다. 행정구역 코드와 방문 위치를 연결하고 MultiPolygon/내부 구멍을 처리한 뒤 네이버 지도 polygon overlay로 빈도별 색을 칠한다. 정적 경계 JSON을 에셋으로 포함하거나 서버에서 캐시할 수 있다. 지도 이미지 에셋은 필요 없다. 주소 없는 수동 핀은 경계 내 위치 판정이 구현되면 통계에 포함할 수 있다.

## 검증

- 장소 유효성, 지역명 정규화, 방문 중복 집계, 한 장소 핀 합치기, 전체 핀 범위 계산 테스트.
- 검색 지연/실패/재시도/화면 폐기와 기존 선택 확인, 원래/새 RPC 선택·명시적 좌표 해제·없는 RPC 실패, 전체 201개 장소 페이지 조회 테스트.
- 서버 검색 테스트 5개: 비로그인/비멤버 차단, 입력 크기 제한, quota 차단, 좌표 변환, 제공자 오류/secret 비노출. `node supabase/functions/naver-place-search/handler_test.ts` (Node 24).
- [SQL 회귀 테스트](../supabase/tests/meetup_places_test.sql)를 별도 PostgreSQL 17에서 실행해 저장·검증·참석 실패 롤백·기존 RPC 호환·RLS 거부·핀 해제·검색 제한을 확인했다. 이 파일은 **빈 임시 DB 전용**이며 실제 Supabase에서 실행하지 않는다.
- 자동 검증 결과와 네이티브/실기기 미검증 범위는 [제품 작업 기록](product_direction.md)에 정리한다.
